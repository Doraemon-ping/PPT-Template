## 2026-09-20：修复接口图片在 PPT 编辑台不显示

### 问题

接口（工作空间）图片字段在「字段配置」的预览里能显示，但到 PPT 编辑台的原页 / 实时预览里就是空白。

### 原因

字段配置的预览是**浏览器直接加载图片地址**，而 PPT 编辑台是**服务端渲染**。服务端两条图片通路都只认 `bytes`、本地文件路径和 `data:` base64：

- `openxml/image_binding.py::decode_image_bytes`（OOXML 定点替换、单元格图片、可视区域图片都走它）
- `renderers/image_renderer.py::_image_stream`（python-pptx 渲染通路）

接口接入的图片字段经 `url_base` 解析后是 **`http://…` 绝对地址**（例如 `http://127.0.0.1:8002/api/machining-dfm/assets/f95d0a5f…`，还没有扩展名），于是被当成"普通文本"直接判失败，图片绑定被跳过。

### 修复

- `decode_image_bytes` 支持 http(s) 图片地址：下载后返回字节，带 15 秒超时、20MB 上限和 24 条 URL 缓存（同一地址在多次绑定 / 多页复用时只下载一次），失败给出可读错误。
- 新增 `is_image_url()` / `is_image_reference()` 判定，并让「文字片段」「公式参数」的拦截、以及旧版 `table_cell → image_region` 兼容判断都用它（原来的 `data:image/` 判断漏掉了 http 图片地址）。
- `image_renderer._image_stream` 统一改为调用 `decode_image_bytes`，两条通路行为一致。
- **前端同样漏判**：模板编辑台用 `data:image/` 判断"这个字段是不是图片"，接口图片字段是 http 地址（还常常没有扩展名），于是绑定时弹「该字段当前是普通文本，不是图片」。现在 `editor_models.js` 新增 `isImageValue()`（data: 图片 / http(s) 图片地址）并让 `isImageSource()` 同时认 `i.` 前缀（服务端字段目录已判定为图片）与这两类值；编辑台里 `updateSelHint`、`bindNow`、`doBind`、文字片段拦截、公式字段拦截都改用它，提示文案也更新为"data:image 图片、http 图片地址，或目录里的图片字段"。

### 验证

- 新增前端测试：`i.` 前缀 + http 值、数组形态、值为空时仍识别为图片，以及文本字段/非图片 URL 不被误判。
- 在真实编辑台页面（工作空间 3 / 真实模板）实测：目录里 5 个图片字段都在，`i._systems.source_5_endpoint_6.product_url[0]` 当前值 `http://127.0.0.1:8002/api/machining-dfm/assets/f95d…` → `isImageSource` **true**（旧规则会拦下并弹错），文本字段 `…fields.cust`（赛力斯 SERES）仍为 false，无控制台异常。

- 新增单测：http 图片下载并命中缓存、404 报错、真正填进图片对象；`is_image_reference` 覆盖 `data:` / http（含带查询串、大写扩展名）/ 本地文件 / 普通文本 / 非图片 URL。
- 新增接口级测试：`POST /api/template/generate` 用 http 图片地址生成，生成物里的 `ppt/media/image1.png` 是真实图片（尺寸与源图一致）。
- 用真实数据实测（重启后的服务）：取最新 Dataset 里的 `images.product_url = http://127.0.0.1:8002/api/machining-dfm/assets/f95d0a5f…`（无扩展名）→ `generate` 返回 200，媒体部件为 PNG、**788×491**，即真实产品图已成功下载并写入 PPT。
- 全量 Python 测试 217 项通过；`test_exact_template_engine` 仍因本机缺少 `1-基础数据` 素材目录在导入期报错（既有环境问题）。
- 注意：图片映射必须带 `url_base`（用「图片」类型保存时会自动写入），否则数据集里仍是相对路径；服务端预览有 24 条 / 90 秒缓存，改完数据若仍显示旧图，稍等或改动一下数据再看。

## 2026-09-20：一组数据只取其中一条（数组下标 / 过滤 / 切片）

### 背景

接口返回的是数组（设备1、设备2 …）时，原来既看不懂也配不出来「只要其中一个值」。

### 后端

- `response_parser` 从 `jsonpath_ng` 换成 `jsonpath_ng.ext`：基础解析器只支持字段、`[*]` 和 `[0]`，过滤器 `[?(@.qty>4)]`、切片 `[1:]` 会直接词法报错（`connector_binding` 里预留的 `[?` 集合标记因此一直是死代码）；换 ext 后两类都能用。
- 取值语义不变：路径里出现 `[*]` 或 `[?` → 保留列表（走整表绑定）；`[0]` 这类取单条 → 得到单个值（走文字 / 图片绑定）。

### 前端（高级设置 → 4 字段）

- 选中的参数属于一组数据（路径含 `[*]`）时，配置面板出现「取第几条（共 N 条）」：选「全部」按整表绑定；选「第 N 条」把路径里的 `[*]` 换成 `[N-1]` 只取那一条，类型自动在「表格 ↔ 文字 / 图片」之间切换，预览同步显示那一条的值。
- 存量映射写成 `[N]` 时，左栏仍由对应的可选参数项代表（显示实际路径 `$.x[1].y → fields.…`），不再重复出现一条「自定义」；点开时「取第几条」按实际路径回填。
- 预览用的前端 JSONPath 求值补上数值下标 `[N]`。
- 修复 `pickerMappingFor` 被定义两次、后定义的旧版本覆盖新版本，导致 `[N]` 映射识别不到的问题。

### 验证

- 后端新增测试：下标取单值（`$.machines[0].name` → 标量 `"设备1"`）、过滤器 `[?(@.qty>4)]`、切片 `[1:]`，以及非法表达式仍然报 `ApiResponseError`。
- 无头 Edge 用一次性临时连接（`/api/machining-dfm/projects` 返回 3 条）实测：选中 `$.projects[*].id` 出现「取第几条（共 3 条）」，选第 2 条后路径变 `$.projects[1].id`、预览显示第 2 个项目的编号、保存为 `fields.id`；数组本身选「全部」保存为 `tables.projects`；已存在的 `[1]` 映射在左栏显示「已配置」、点开回填源路径与「第 2 条」。
- Python 测试 214 项通过；`test_exact_template_engine` 仍因本机缺少 `1-基础数据` 素材目录在导入期报错（既有环境问题）。

## 2026-09-20：字段配置改为「逐个参数引导配置」

### 后端

- 新增只读接口 `POST /api/connectors/endpoints/{endpoint_id}/discover`：用接口现有参数（缺省走参数默认值，也可传 Runtime Parameters / Context）调用一次外部接口，返回 `discover_fields()` 的完整字段目录（源路径、原字段名、建议目标、中文名、示例值、类型、业务分组、置信度）、记录条数、TARGET_FIELDS 目录、已映射的源路径，以及用于预览的原始响应。不创建 Dataset，也不改写来源状态。
- 预览数据超过 `PREVIEW_MAX_CHARS`（40 万字符）时不回传，改用 `raw_truncated` 标记，前端退回只用字段样例值预览。
- `friendly_error` 增加 `ApiConfigurationError` 分支：接口/连接未启用或请求参数没配齐时，提示去「2 接口 / 3 参数」检查，而不是笼统的「测试连接失败」。

### 前端（高级设置 → 4 字段）

原来的「表格里勾选 + 批量添加」改成主从引导流程：**读参数 → 左侧选一个 → 右侧配置 → 保存 → 自动跳下一个**。

- 左栏列出接口真实返回的全部可选参数，**并合并已配置的字段映射**：既包括与可选参数对应的映射（显示「已配置」），也包括手工写的、不在字段目录里的映射（显示「自定义」）。没点「读取可选参数」时也能看到并编辑现有映射；每项显示中文名、源路径、示例值或目标字段和状态。
- 右栏是单条的配置区：**源字段（JSONPath）**（可选参数只读，自定义映射可改）、**分组**（可直接输入新分组名，带已有分组建议）、**类型**（文字 `fields.` / 图片 `images.` / 表格 `tables.` 三选一，按字段类型自动预选）、**目标字段名**、**中文显示名**。
- **预览**随类型实时切换：文字显示真实取值，图片按 `url_base` 拼出地址并尝试加载缩略图（加载不到会说明是外部系统认证/跨域限制），表格按字段目录列出列名并展示前 3 行。
- 顶部显示「已配置 N / 总数」进度；按钮为「保存并配置下一个 / 仅保存 / 取消」，保存后自动跳到下一条未配置参数并提示继续配置谁；全部配完会提示已完成。编辑已有映射时保存走 PATCH，不会新增记录。
- 映射列表每条改为「配置 / JSON / 删除」：「配置」把该映射送进上面的引导面板（同一套分组、类型、预览），「JSON」才打开手写表单（值翻译 `enum`、表格列名 `column_labels` 等）。
- 删除独立的手写映射表单（原「高级（可选）：手写 JSONPath / 值翻译 / 表格列名」整块）：字段映射只在一个地方维护 —— 左侧选参数/映射，右侧配置。映射列表每条只保留「配置 / 删除」。
- 手写表单独有的两项能力并入右侧配置面板的「更多设置（可选）」：**值翻译**（原值→新值对照 + 兜底值，保存时自动把 `transform_type` 设为 `enum`，清空则回到 `none`）和**表格列中文名**（`column_labels`）。编辑已有 enum 映射时该区块自动展开并回填。
- 保存改为以界面上的值为准：之前「填入示例」是程序赋值、不触发 `input`，导致示例填了但保存丢失（如值翻译存成 `none`）；现在保存前统一从输入框取值，示例按钮也会派发 `input` 事件。
- 修复前端更新看不到的老问题：`/ppt` 与 `/template-editor` 返回的 HTML 之前没有 `Cache-Control`，浏览器会启发式缓存旧页面，改完前端刷新仍是旧版；现在两个页面都返回 `Cache-Control: no-cache, must-revalidate`，普通刷新即回源。
- 切换连接或接口会清空字段目录，避免沿用上一个接口的字段。
