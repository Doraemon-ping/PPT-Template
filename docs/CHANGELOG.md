# 项目更新记录

最后更新：2026-09-10

本文按时间记录表单平台、PPT 模板工作台和生成引擎的已完成变更。具体实现边界以
[多表单应用平台交接](FORM_PLATFORM_2026-09-09.md)和各专项文档为准。

## 2026-09-10：允许未完全绑定的 HTML 表单生成 PPT

- 导入 HTML 的表单应用不再因 PPT 模板存在未绑定目标而返回 422。
- 默认 `missing=keep` 下，未绑定对象保留模板原内容，已绑定对象正常替换。
- 生成接口通过 `X-DFM-Unbound-Targets` 返回未绑定目标数量，不再把它们作为阻断错误。

## 2026-09-10：切换项目后 PPT 使用最新数据

- 表单中心和 PPT 工作台的 API 请求显式使用 `cache: no-store`，避免同一项目 URL 更新后读取浏览器旧快照。
- 项目详情接口返回 `Cache-Control: no-store, max-age=0`。
- 新增回归验证：同一项目从 `Customer` 更新为 `New Energy` 后，下一份 PPT 只包含新值。

## 2026-09-09：模板目标驱动绑定与多表单平台

### 已完成

- 新增表单中心 `/forms`。HTML 可以先静态识别字段，也可以对受支持的复杂页面选择“原样运行 HTML + 数据桥接”。
- 新增独立表单应用、命名数据项目、版本历史、恢复、归档、JSON 导出、并发 revision 校验和服务端工作台草稿。
- 模板、方案、草稿按 `app_id` 隔离。新导入的表单默认没有 DFM 模板，用户可以上传自己的 PPT。
- 复杂 DFM/报价 HTML 以隔离 iframe 运行；原页面的 `G / PR / MDB / TDB / IS / FDB / IDB / VH` 快照可保存、恢复，并动态生成字段目录。
- 原样 HTML 的字段目录保留稳定的源路径，例如 `G.cust`，并提供中文标签和原始字段路径提示。
- `/api/template/scan` 返回 `binding_targets`，列出每个 PPT 页、形状和占位符目标。
- 工作台新增“当前 PPT 页的模板目标”面板。用户先选择导入 PPT 中的目标对象，再从当前表单目录选择来源字段，方案保存显式的 `PPT 目标 → 表单源` 关系。
- 模板占位符不再被当作跨表单通用字段。原样 HTML 不会自动套用 `custName`、`partNo` 等固定 DFM 名称。
- 原样表单正式生成前检查最终 OOXML；仍残留的模板占位符会返回未绑定清单，不再静默下载带 `{f.xxx}` 的 PPT。
- 历史方案如果明确写入旧 DFM 字段路径，仍提供限定范围的迁移解析；新方案目录和默认上下文不注入这些别名。

### 预览性能优化

- 编辑台在等待 PowerPoint 数据渲染时立即显示原模板底图，不再出现空白画布；输入变化采用 450ms 防抖，快速连续修改只提交最后一次请求。
- 服务端新增进程内 LRU 预览缓存（24 条、90 秒 TTL），相同模板/页/绑定/数据请求直接返回已渲染 PNG，避免重复启动 PowerPoint。
- `app/report/ppt/slide_preview.py` 配合 `tools/preview_worker.ps1` 复用一个隐藏 PowerPoint COM 进程；worker 异常时自动回退原有一次性导出路径。
- Windows 独立版 PyInstaller spec 已把 preview worker 一并打包，绿色版仍可在缺少 PowerPoint 时安全回退。
- PowerPoint 预览默认导出从 1600×900 调整为 1280×720，保持 16:9 选择精度并减少导出和传输开销；缓存指纹包含尺寸，切换尺寸不会复用旧图片。
- `X-DFM-Preview-Cache` 响应头标记 `hit`/`miss`，便于排查慢请求和后续监控。

### 预览稳定性修复

- 修复 PowerPoint 自动化偶发返回 `WinError 6（句柄无效）` 时，编辑台原页预览直接 503 的问题：常驻渲染器失败后会释放失效 COM/子进程、重建并重试一次；仍失败时自动改用隔离的一次性导出器，该导出器同样会重试一次。
- 远端部署更新代码后需要重启 Uvicorn 服务，使已失效的 PowerPoint worker 被替换；浏览器无需重新导入模板。
- 新增 `tools/check_preview_environment.ps1`，可在发布目录检查 PowerShell、预览脚本是否完整，以及运行服务账户能否创建 PowerPoint COM；同时明确区分“生成 PPTX”（不依赖 Office）和“原页 PNG 预览”（依赖桌面 PowerPoint）。
- 直接验证最终 `release/DFM报告生成器_win64`：以打包 EXE 启动并请求 demo 原页预览返回 HTTP 200 / PNG。构建脚本现在校验完整发布目录并生成同名 ZIP，避免误发缺少模板的数据 `build_dist` 中间产物。
- 构建脚本在 ZIP 生成后再次确认发布目录仍存在；发布目录和 ZIP 均可交付。已从 ZIP 解压后启动 EXE 复测，原页预览继续返回 HTTP 200 / PNG。

### 验证

- Python：`python -m unittest discover -s tests`，224 项通过（含实时预览缓存和失效 worker 恢复回归）。
- Node：`node --test tests/editor_models.test.cjs tests/native_bridge.test.cjs`，12 项通过。
- 前端内联脚本、对象导航脚本通过 Node 语法检查。
- 本机服务已重启，监听 `127.0.0.1:8000`。
- 本机实时预览 smoke：后台 PowerPoint 渲染器首次请求约 2.6 秒，不同数据的下一次请求约 0.1 秒，相同请求缓存命中约 0.005 秒；响应头正确返回 `miss` / `hit`。

## 2026-09-03：编辑交互、方案复用、分页和图片

- 已保存方案可以复用其中某一页，连同绑定、公式、图片、重复规则和条件复制到当前方案；来源方案不被修改。
- 新增中文公式编辑器：搜索参数、插入文字/分子/分母和运算符，保存时还原兼容的模板表达式。
- 新增对象搜索、对象列表、shape ID 选择、键盘选择、绑定草稿、撤销未保存修改和实时预览状态。
- 整表绑定支持按表头列映射、指定每页行数、自动续页、统一参考行高、续页预览和过密提示。
- 修复表格图片绑定：支持单元格区域图片、旧方案误存的图片文本类型和缺图保留原模板。
- 修复跨模板导入的 tags、母版/版式 ID、notes 关系和资源依赖冲突；小模板跨页/混合模板生成通过 PowerPoint 冒烟验证。

## 2026-09-02：Open XML 模板生成引擎

- 新增 ZIP/OOXML 定点编辑引擎，保留未绑定部件和原模板样式，不使用 `python-pptx` 重存正式复杂模板。
- 支持 `{path}` 文本占位符、跨 run 文本替换、图片部件替换、显式形状绑定、表格单元格/整表绑定、公式图片和图片区域。
- 支持 Deck 编排：按页取用、重复页、条件页、跨模板拼页，以及 `deck` / `in_place` 两种输出模式。
- 新增模板注册、模板扫描、形状检查、实时预览、方案保存和方案生成接口。
- 保留原 `/api/ppt` 旧生产链路，模板引擎通过独立接口逐步验证。

## 当前已知边界

- 原样运行目前提供 `dfm_quote_v1` 适配器，针对指定 DFM/报价 HTML；任意 React/Vue 或自定义运行时页面不会被伪装成已完成桥接。
- 官方 84 页复杂模板的整份 `in_place` 路径优先；任意页面子集/重复/跨模板组合仍需按具体模板做 PowerPoint 验收。
- 原页实时预览依赖 Windows/PowerPoint 渲染通道。
- 当前是本机单实例存储，没有登录、用户权限、云端备份和多人协作隔离。
